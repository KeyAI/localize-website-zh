# 仓库与交付规范

## 1. 标准目录

```text
origin/                   # 未修改的原文基准
zh/                       # 中文化网站
docs/
  SOURCE_MANIFEST.md
  LOCALIZATION_BRIEF.md
  GLOSSARY.md
  STYLE_GUIDE.md
  PROGRESS.md
  DECISIONS.md
  QA_REPORT.md
  progress/               # 各 workstream 独立记录
README.md
.gitignore
```

不要再引入含义重复的 `source/`、`site/`、`dist/` 和 `final/`。如需生成部署树，使用一个语义清晰且被忽略的目录，例如 `publish/`。

## 2. 何时需要构建脚本

直接部署 `zh/`，除非至少满足一项：

- 第三方发行包很大且可按固定版本重建；
- 需要编译、打包、重写基础路径或生成静态路由；
- 部署平台要求不同目录结构；
- 需要从白名单提取运行时依赖；
- 中文源码包含不应直接发布的过程文件。

构建脚本应：

- 提供一个清晰入口，例如 `make build` 或 `scripts/build.sh`；
- 固定第三方版本，并保存校验或来源依据；
- 从空输出目录稳定生成相同结构；
- 使用临时目录构建，再替换最终产物；
- 不依赖个人绝对路径、浏览器会话或秘密环境状态；
- 不修改 `origin/` 或 `zh/`；
- 不把完整通用依赖复制到多套源码目录。

不要为了“看起来专业”增加无必要的构建层。

## 3. Git 中必须提交

- `origin/` 中不可重新获取或作为翻译基准所需的原始内容；
- `zh/` 中所有翻译成果、图片、样式、脚本和运行所需本地资源；
- 过程文档、术语表和最终 QA 记录；
- 构建脚本、依赖白名单、锁文件和必要配置；
- README 与适用的许可证或来源说明。

## 4. 默认不提交

- 构建产物和临时预览目录；
- 缓存、日志、抓取中间文件和浏览器配置；
- 本地部署状态、凭据和会话数据；
- 能由锁定版本准确重建的大型第三方发行包；
- 编辑器和操作系统生成文件。

如果某个文件不能稳定重建、属于翻译成果或影响用户所见内容，就不能仅因为体积大而忽略。

## 5. README 最低内容

- 中文项目名称和原站链接；
- 在线地址（如有）；
- 项目结构；
- 翻译方法与质量原则；
- 构建或直接运行方式；
- 原作者、来源、许可和非官方声明；
- 问题反馈方式。

在结构和构建方式稳定后再定稿 README。

## 6. 最终验证

从干净状态执行：

1. 生成或直接运行 `zh/`；
2. 打开全部入口和代表性深链；
3. 检查导航、公式、图片、字体、媒体、交互和动态文案；
4. 检查本地资源 404、控制台错误和意外外链；
5. 对照 `origin/` 验证关键交互语义；
6. 检查过程文档、`.gitignore` 和 Git 状态；
7. 将执行范围、结果、未覆盖部分和已知限制写入 `QA_REPORT.md`。

报告“已验证什么”，不要把未执行的路径描述为通过。

## 7. Git-ready 完成条件

- `PROGRESS.md` 已收口，没有仍标为“进行中”的已完成工作；
- `QA_REPORT.md` 已填写真实结果，不保留空模板；
- README、`.gitignore`、来源和许可说明已定稿；
- 目录已是本地 Git 仓库；若原先不是，执行 `git init`；
- `git status` 中没有无来源的缓存、日志、临时构建或个人状态；
- 未经用户明确要求，不创建提交、不添加远程、不推送。
