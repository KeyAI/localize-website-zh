# 抓取与内容清单

## 1. 选择基准

按以下优先级确定事实源：

1. 用户明确提供的完整源码；
2. 官方可下载或可构建源码；
3. 经授权访问的线上网站及其运行时资源。

若源码与线上表现不一致，分别记录“源码事实”和“运行时事实”。不要用线上抓取静默覆盖用户提供的基准。

## 2. 识别网站类型

| 类型 | 主要证据 | 捕获重点 |
|---|---|---|
| 静态站 | HTML 直接包含主要内容 | 镜像路由、页面依赖和重写后的链接 |
| SPA | HTML 外壳、打包 JS、客户端路由 | 动态分块、路由表、JSON/API、History fallback |
| SSR/SSG | 服务端 HTML 加 hydration | 各路由 HTML、客户端分块、构建清单 |
| 文档生成器 | 明确源码或构建配置 | 优先保存 Markdown/MDX/模板和构建环境 |
| 登录站点 | 会话后才显示内容 | 确认授权、账号范围、可交付边界和敏感信息处理 |

## 3. 完整捕获清单

### 页面与导航

- 入口、目录、分页、语言切换、错误页和所有目标路由；
- canonical、重定向、hash 路由、客户端路由和深链；
- robots、sitemap、manifest 和 service worker 注册。

### 资源

- CSS 中的 `url()`、`@import` 和字体；
- JavaScript 动态导入、Worker、WASM、JSON 和模板；
- `src`、`srcset`、懒加载属性、picture/source、海报和字幕；
- SVG 外链、Canvas 贴图、精灵图、图标和媒体；
- 交互后才加载的章节、模态框、标签页和折叠区资源。

### 用户可见文案

- HTML 文本、head 元数据和结构化数据；
- `title`、`alt`、`placeholder`、`aria-*`、表单值；
- JS/JSON 字典、模板字符串、状态机和错误映射；
- Canvas/SVG 标签、图例、时间轴和字幕；
- 第三方组件的菜单、帮助、警告和无障碍界面。

## 4. 运行时补全

对代表性入口和交互执行一次资源追踪：

1. 清空浏览器缓存或使用隔离上下文；
2. 打开各路由并等待稳定状态；
3. 触发懒加载、标签页、模态框、菜单和代表性交互；
4. 记录请求 URL、状态码、重定向和动态分块；
5. 将缺失的同源功能资源补入 `origin/`；
6. 对第三方 API、分析脚本和外部嵌入决定“保留外链、替代、排除或本地化”，并记录理由。

网络记录证明“这次运行请求过”，不能单独证明“其他文件永远无用”。把依赖分为：

- 当前默认路径必需；
- 条件交互必需；
- 可重建的第三方依赖；
- 与目标站无关的发行包能力；
- 尚未验证。

## 5. 防止污染基准

排除：

- 浏览器翻译或无障碍扩展注入的属性和样式；
- 开发者工具、代理、广告拦截器产生的内容；
- 登录令牌、Cookie、个人数据和调试响应；
- 抓取工具生成但原站不存在的索引页；
- 失败下载保存成的 HTML 错误页。

## 6. `SOURCE_MANIFEST.md` 最低内容

- 入口与范围；
- 获取日期和方法；
- 路由清单；
- 文件数量与主要类型；
- 外部域名和依赖；
- 运行时补充资源；
- 源站已有失败；
- 身份验证或动态后端边界；
- 关键版本与校验信息；
- 未捕获或无法静态化的内容。

开始翻译前，确保 `origin/` 可以作为稳定的逐文件对照基准，并将其复制为 `zh/` 一次。
